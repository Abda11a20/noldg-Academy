# Backend contract differences

Evidence below was read from `referencebackend/` only. No backend code is imported into the frontend.

| Topic                                   | Target contract                                                                                                             | Current backend                                                                                                                                                                                                                                                                                                                    | Evidence                                                                                                                                                                                                                                           | Status                                                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Auth token header and refresh           | `Authorization: Bearer`; short-lived access token plus refresh cookie and refresh endpoint                                  | Authentication reads `req.headers.token`. The auth router has login/logout/profile/register routes and no refresh route.                                                                                                                                                                                                           | `referencebackend/src/middleware/authentication.js`; `referencebackend/src/modules/auth/auth.router.js`                                                                                                                                            | Adapter/header strategy defaults to the legacy header until refresh support exists.                                             |
| Token lifetime                          | Access-token lifetime is explicit in the login response/session contract                                                    | `ACCESS_TOKEN_TTL` controls expiry, defaults to `5h`, and accepts `none`.                                                                                                                                                                                                                                                          | `referencebackend/src/utils/token.js`                                                                                                                                                                                                              | Temporary backend behavior; target refresh design remains pending.                                                              |
| Device identity                         | Opaque server-managed device/session identity; client does not invent trust identity                                        | Server hashes detected IP plus user-agent with SHA-256. Device limit defaults to one active device per account.                                                                                                                                                                                                                    | `referencebackend/src/modules/user/device.utils.js`; `referencebackend/src/modules/auth/auth.controller.js`                                                                                                                                        | Backend derives identity; frontend must not send a guessed device ID.                                                           |
| Student signup fields                   | `name`, `email`, `phone`, `password`; credentials are normalized and secret-free user data is returned                      | Registration schema requires exactly those four fields; registration response returns public user data, while login separately returns `token`.                                                                                                                                                                                    | `referencebackend/src/modules/auth/auth.validation.js`; `referencebackend/src/modules/auth/auth.controller.js`                                                                                                                                     | Verified.                                                                                                                       |
| Package access and pricing              | Product type and access grant are explicit; prices are represented without floating-point loss                              | A package grants access across its course; a standalone lesson product grants that lesson. Product/order prices are integer EGP, while some ledger amounts use Decimal.                                                                                                                                                            | `referencebackend/src/modules/lesson/lesson-access.utils.js`; `referencebackend/prisma/schema.prisma` (`Product`, `Order`, `LedgerEntry`)                                                                                                          | Common money schema accepts integer values or decimal strings until domain contracts normalize.                                 |
| Order reference and expiry              | Stable opaque reference plus explicit expiry or no-expiry contract                                                          | References use `ORD-` plus a UUID. The Order schema and creation flow have no expiry timestamp or expiry assignment; statuses are pending payment/review, approved, rejected.                                                                                                                                                      | `referencebackend/src/modules/order/order.controller.js`; `referencebackend/prisma/schema.prisma` (`Order`); `referencebackend/src/utils/constant/enum.js`                                                                                         | No order expiry behavior found in these paths; frontend must not invent a deadline.                                             |
| Money types                             | EGP amount is an integer or a Decimal string, never binary floating point                                                   | Product/order price fields and payment amount are integers; commission/teacher/platform amounts are Float in order and Decimal in ledger rows.                                                                                                                                                                                     | `referencebackend/prisma/schema.prisma` (`Product`, `Order`, `Payment`, `LedgerEntry`)                                                                                                                                                             | Mixed legacy representation; target schema accepts integer or decimal string.                                                   |
| Rating comment                          | Optional plain-text comment, bounded length                                                                                 | `comment` is optional, trimmed, max 500 characters, and empty string is allowed.                                                                                                                                                                                                                                                   | `referencebackend/src/modules/rating/rating.validation.js`                                                                                                                                                                                         | Verified.                                                                                                                       |
| Question types                          | Discriminated question schema with type-specific answer shape                                                               | `single_choice`, `multiple_choice`, `true_false`, `essay`; objective types require answer keys, essays do not.                                                                                                                                                                                                                     | `referencebackend/src/utils/constant/enum.js`; `referencebackend/src/modules/question/question.validation.js`                                                                                                                                      | Verified.                                                                                                                       |
| Video delivery                          | Session-authorized media URL with server-controlled expiry and playback checks                                              | Cloudinary authenticated assets are returned through short-lived signed URLs only for an active playback session. URL lifetime is at most one hour and bounded by session/lesson expiry; playback leases are two minutes.                                                                                                          | `referencebackend/src/modules/lesson/lesson-access.controller.js`; `referencebackend/src/modules/learning/learning.utils.js`; `referencebackend/src/modules/learning/learning.controller.js`                                                       | Verified.                                                                                                                       |
| Auth base path and student registration | `/api/auth/register/student` accepts target profile fields and terms, with email verification response                      | `/api/auth/register` accepts `name`, `email`, `phone`, `password`; no parent phone, track, terms, OTP, or student path. It returns `{success,message,data}` with a public user.                                                                                                                                                    | `referencebackend/src/bootStrap.js`; `referencebackend/src/modules/auth/auth.router.js`; `referencebackend/src/modules/auth/auth.validation.js`; `referencebackend/src/modules/auth/auth.controller.js`                                            | Live adapter drops unsupported fields; target-only verification degrades to a localized state.                                  |
| Login and profile                       | Email/password returns access token, expiry, and normalized user; `GET /auth/me`                                            | Login accepts exactly one of email or name plus password and returns `{success,message,token}`. Profile is `GET /api/auth/` and returns `{success,message,data}`.                                                                                                                                                                  | `referencebackend/src/modules/auth/auth.validation.js`; `referencebackend/src/modules/auth/auth.controller.js`; `referencebackend/src/modules/auth/auth.router.js`                                                                                 | Live adapter maps token and fetches profile; backend expiry is not returned.                                                    |
| Teacher signup                          | `/api/auth/register/teacher`, multipart with offerings and terms, target verification/status                                | `POST /api/teachers/signup` accepts multipart `name,email,phone,password,bio,offerings`; `offerings` is parsed from JSON, `image` is optional, terms are unsupported. Success is `201` with `{success,message,data:{user,application}}`; new account is marked verified and application starts pending.                            | `referencebackend/src/bootStrap.js`; `referencebackend/src/modules/teacher/teacher.router.js`; `referencebackend/src/modules/teacher/teacher.validation.js`; `referencebackend/src/modules/teacher/teacher.controller.js`                          | Live adapter maps route and body. Email verification is not available.                                                          |
| Email OTP and password recovery         | Email verification and email-only recovery with six-digit, five-minute OTP                                                  | No email-verification or resend-code route exists. Forgot/reset routes exist, but reset delivery is via WhatsApp; reset codes have six digits, five-minute expiry, and at most five attempts.                                                                                                                                      | `referencebackend/src/modules/auth/auth.router.js`; `referencebackend/src/modules/auth/password-reset.controller.js`; `referencebackend/src/modules/auth/password-reset.utils.js`                                                                  | OTP capability disabled in live mode; recovery route works only when backend WhatsApp settings allow it.                        |
| Password and phone validation           | Client mirrors server rules; Egyptian mobile validation follows backend contract                                            | Password requires at least 8 chars, uppercase, lowercase, digit, special char from `#?!@$%^&*-`, and at most 72 UTF-8 bytes. Phone is trimmed and capped at 64 characters; no Egyptian-specific pattern is enforced.                                                                                                               | `referencebackend/src/utils/generalFields.js`; `referencebackend/src/modules/auth/auth.validation.js`                                                                                                                                              | Client mirrors password rule and does not invent a phone-country restriction.                                                   |
| Legacy error envelope and codes         | `{error:{code,message,details?}}` with stable target codes                                                                  | Errors are `{success:false,message}` with status code; there is no machine-readable error code or field details. Rate limits return HTTP 429. Duplicate registration combines email/name conflicts.                                                                                                                                | `referencebackend/src/utils/appError.js`; `referencebackend/src/modules/auth/auth.controller.js`; `referencebackend/src/middleware/rate-limit.js`                                                                                                  | Adapter maps identifiable statuses; ambiguous legacy messages use generic localized errors.                                     |
| Academic catalog                        | Public systems, tracks and subjects per track for signup                                                                    | `GET /api/academic/catalog` requires authentication and returns only systems, stages, and grade numbers; tracks/subjects are separate authenticated routes.                                                                                                                                                                        | `referencebackend/src/modules/academic/academic.router.js`; `referencebackend/src/modules/academic/academic.controller.js`                                                                                                                         | `publicCatalog` is disabled in live mode; onboarding shows a localized unavailable state.                                       |
| Teacher application status              | `GET /auth/me` includes status and optional rejection reason                                                                | `GET /api/teachers/me/application` is authenticated for student/teacher and returns `{success,message,data}` with `approvalStatus` and offerings. No rejection-reason field is defined.                                                                                                                                            | `referencebackend/src/modules/teacher/teacher.router.js`; `referencebackend/src/modules/teacher/teacher.controller.js`; `referencebackend/db/models/teacher-profile.model.js`                                                                      | Adapter maps `approvalStatus`; rejection reason remains absent.                                                                 |
| Device changes                          | Create/list own change request with pending/approved/rejected state                                                         | No device change request route/model was found. Current device id is server-derived from IP and user-agent; limit defaults to one active device per account.                                                                                                                                                                       | `referencebackend/src/modules/user/user.router.js`; `referencebackend/src/modules/user/device.utils.js`; `referencebackend/src/middleware/authentication.js`                                                                                       | `deviceChangeRequest` disabled in live mode.                                                                                    |
| Academic route permissions and enums    | ADMIN and SUPER_ADMIN can manage tracks and subjects; target systems are `azhar`/`egyptian_bacc`, stages `prep`/`secondary` | Academic writes are guarded by SUPER_ADMIN only. Backend uses `al_azhar`, `egyptian_baccalaureate`, and `preparatory`; American Diploma is secondary-only and grades are 1–3. Read routes require authentication.                                                                                                                  | `referencebackend/src/modules/academic/academic.router.js`; `referencebackend/src/modules/academic/academic.validation.js`; `referencebackend/src/utils/constant/enum.js`                                                                          | F3 adapter maps enums; backend must broaden write access for ADMIN and align the target contract.                               |
| Academic list shape and filtering       | `{items,page,pageSize,total}` and filters `q`, `sort`, `active`                                                             | `GET /academic/tracks` filters by system, stage, `isActive`; GET subjects filters by `isActive`. Both return all matching records under `data` with `count`; no search, sort, or pagination.                                                                                                                                       | `referencebackend/src/modules/academic/academic.router.js`; `referencebackend/src/modules/academic/academic.controller.js`; `referencebackend/src/modules/academic/academic.validation.js`                                                         | Live adapter normalizes response fields and combines active/inactive reads; search is local and is not safe for large catalogs. |
| Track subject management                | Track mappings can be listed, linked, and unlinked; records in use are disabled instead of hard-deleted                     | `GET/POST /academic/tracks/:trackId/subjects`, `DELETE /academic/tracks/:trackId/subjects/:subjectId`. Delete removes only the mapping. The backend has no DELETE track/subject route; PATCH toggles `isActive`.                                                                                                                   | `referencebackend/src/modules/academic/academic.router.js`; `referencebackend/src/modules/academic/academic.controller.js`                                                                                                                         | Mapping contract aligns; list pagination is absent.                                                                             |
| Teacher application administration      | Searchable paginated list, detail route, reasoned reject, race conflict `ALREADY_REVIEWED`                                  | `GET /teachers/applications?page=&limit=&status=` is account-manager protected and returns `{data,count,pagination}` with profile and user information. `PATCH /teachers/applications/:applicationId/review` accepts `{status}`. No detail endpoint or rejection reason field; concurrent missing/pending application returns 404. | `referencebackend/src/modules/teacher/teacher.router.js`; `referencebackend/src/modules/teacher/teacher.controller.js`; `referencebackend/src/modules/teacher/teacher.validation.js`; `referencebackend/src/modules/teacher/teacher.controller.js` | List adapter maps pagination and profile fields. Live detail/rejection reason and `ALREADY_REVIEWED` remain unsupported.        |
| Teacher resubmission                    | Multipart profile update with same fields as signup after rejection                                                         | `POST /teachers/applications` accepts only `bio` and `offerings` plus optional `image`; `offerings` is parsed from JSON. It resubmits rejected applications. The profile patch route is a separate `PATCH /teachers/me/profile`.                                                                                                   | `referencebackend/src/modules/teacher/teacher.router.js`; `referencebackend/src/modules/teacher/teacher.validation.js`; `referencebackend/src/modules/teacher/teacher.controller.js`                                                               | Live adapter drops name, email, and phone from resubmission.                                                                    |
| Account status list and updates         | Teacher status filter and `{status,reason}` updates                                                                         | `GET /users?page=&limit=` returns non-admin users without role/status filtering. `PATCH /users/:userId/status` accepts `{status}` only.                                                                                                                                                                                            | `referencebackend/src/modules/user/user.router.js`; `referencebackend/src/modules/user/user.validation.js`; `referencebackend/src/modules/user/user.controller.js`                                                                                 | Teacher account status list is disabled in live mode; the live adapter drops the target reason.                                 |
