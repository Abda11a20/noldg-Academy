# F8A — تقرير التنفيذ والتسليم

## 1. الملخص

نُفذت المرحلة على الفرع `feat/f8a-assessments-teacher` ووصل التنفيذ إلى الحد الثاني المحدد في المواصفة: **طبقة API وبنك أسئلة المعلم**. تشمل النتيجة عقود الأسئلة والتقييمات المستهدفة، توافقًا أوليًا مع أشكال الباك الحالية، قدرات قابلة للتعطيل في الوضع الحي، mocks وبيانات تجريبية، عناصر UI مشتركة، ومسار `/teacher/questions` بالعربية والإنجليزية.

لم تُنفذ بعد قوائم ومنشئ الاختبارات والواجبات، كويز الدرس، أو صفحات النتائج. لذلك لا تُعد F8A مكتملة وظيفيًا. لم تُضف أي dependency ولم يُشغّل `pnpm install` ولم يُعدّل `node_modules`. مجلد `referencebackend/` بقي للقراءة فقط ولم يُعدّل أو يُستورد من الكود.

## 2. الملفات المنشأة أو المعدلة

- **API:** عقود Zod للأسئلة والتقييمات، محول target/live، capabilities، endpoints لبنك الأسئلة، mocks وfixtures تشمل 40 سؤالًا، واختبارات العقود والمحولات والطلبات ضمن `packages/api/src/`.
- **UI:** `SearchableMultiSelect` و`NumberField` و`OrderList` واختباراتها وتصديرها من واجهة `packages/ui` العامة.
- **Portal:** feature بنك الأسئلة في `apps/portal/src/features/question-bank/`، route محمّل كسولًا، عنصر تنقل المعلم، ترجمتا `questions.json`، واختبارات الصفحة.
- **جودة الاختبارات:** حارس `console.warn` و`console.error` المشترك صار في `packages/api/test/console-guard.ts` لتكون تبعية Vitest معلنة ضمن الحزمة المالكة لها. إزالة export غير مستخدم أصلحت Knip. أُضيف انتظار صريح لطلب حالة الجهاز في اختبار E2E لتفادي السباق، وأزيل تعارض `NO_COLOR` من بيئة Playwright.
- **التوثيق:** `docs/api-target-assessments.md`، `docs/contract-differences.md`، ADR-019 وADR-020، `README.md`، `CONTEXT.md`، وهذا التقرير.
- **تجاهل الملفات المحلية:** أُضيف `*.log` إلى `.gitignore`.

لا توجد تغييرات في ملفات manifests أو lockfile، ولا صور جديدة ملتزمة في Git.

## 8. الانحرافات عن المواصفة

- توقفت عند الحد الثاني المسموح: **API layer and question bank**. لم أبدأ assessment/exam/homework builder، صفحات النتائج، أو إضافة كويز الدرس.
- مجموعة E2E القائمة اجتازت الاختبارات الثلاثة، لكنها لا تحتوي بعد على سيناريو بنك الأسئلة أو مسارات التقييم الجديدة.
- لم تُلتقط أو تُراجع لقطات شاشة خاصة بصفحة الأسئلة؛ الفحص البصري اليدوي غير مثبت. لم تُحفظ صور جديدة في Git.
- `questionImages` و`questionMetadata` و`questionArchive` ومرشحات البنك المستهدفة غير متاحة في live mode بسبب عقد الباك الحالي، لذا تُعطل capabilities المقابلة بدل إظهار دعم غير موجود.
- لا توجد تبعيات جديدة أو عمليات تثبيت.

## 9. الافتراضات

- عقد F8A المستهدف هو المرجع للواجهة؛ المحول لا يغيّر أو يستورد كود الباك.
- عند live mode، لا تُعرض legacy essay وtrue/false وmultiple-answer كمحرر قابل للتعديل؛ تظهر كمدخلات غير مدعومة للقراءة فقط.
- قيم المعرفات التي لا يتوفر لها endpoint اختيار مناسب تُدخل حاليًا كمعرفات، ولا تخترع الواجهة قوائم أكاديمية أو طلابًا.
- قواعد وقت التقييم والدرجات والأهلية ومحاولات الطالب يقررها الباك؛ الواجهة لا تحسب درجات أو استحقاقًا.

## 10. الأسئلة المفتوحة

- هل واجهة اختيار المادة والدرس للـ question metadata ستأخذ بياناتها من endpoints حالية، أم ستُضاف إلى عقد API لاحقًا؟
- هل يعتمد فريق الباك دعم الصور والأرشفة والشرح والربط بالمادة/الدرس وحقول difficulty قبل تشغيل capabilities في live mode؟
- ما السلوك النهائي المطلوب لأسئلة legacy متعددة الإجابات عند عرض تفاصيل سؤال داخل تقييم قديم؟ العقد الحالي يحددها غير مدعومة في بنك MCQ.

## 11. المخاطر والدين التقني

- فرق العقد مرتفع: الباك الحالي يقبل أنواع أسئلة أكثر، لكنه لا يوفر الصور والشرح والmetadata والأرشفة المستهدفة. capabilities الحالية تمنع الواجهة من ادعاء دعم live لهذه الحقول.
- كود assessment target موجود في العقود والتوثيق فقط حتى الآن؛ لا توجد واجهة لإدارة التقييمات أو النتائج.
- selectors للـ subject وlesson metadata تعتمد على IDs يدويًا لحين حسم مصدر البيانات.
- عدد أسئلة fixtures 40، لكنه لا يمثل قياس أداء مع بنك إنتاجي أكبر.
- لم يُجر تدقيق الحزم، ولم يُفحص الأداء على بيانات حقيقية أو بيئة الباك.

## 13. ما ينبغي مراجعته أولًا

1. افتح `/teacher/questions` في mock mode وراجع تحرير الخيارات والإجابة الصحيحة، المعاينة، ورسائل العربية/الإنجليزية.
2. راجع `docs/contract-differences.md` وبالأخص فرق أنواع الأسئلة، archive، صور السؤال، وحالة الاختبارات والنتائج.
3. راجع محول legacy في `packages/api/src/adapters/assessments.ts`؛ فهو يقرر عرض الأسئلة القديمة للقراءة فقط.
4. راجع حدود التغطية الجديدة والأدلة في هذا التقرير قبل متابعة builder والنتائج.
